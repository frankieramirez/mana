# Inspect an existing project

Load during Inspect. Read root guidance and the `Control:` pointer before considering installation. An existing verifier, feature map, or root pointer belongs to the project. Preserve it and propose a focused adaptation when it lacks a contract field.

```bash
bash "<SKILL_DIR>/scripts/generate.sh" inspect <repo>
```

This command reads root guidance, package scripts, record-directory presence, and the current Git revision. It never runs package scripts or other project code. Its JSON describes discovered surfaces, not operational readiness. A malformed manifest is an inspection error.

For the first Node recipe, inspect the hosted return briefing implementation, current user route, test assertions, startup/seed/teardown fixtures, dependency lockfile, and release obligations. Record what was actually read. Route aliases are discovery hints; matching one does not establish a defect. Keep the API empty-account behavior distinct from browser empty-state coverage.

Choose the smallest existing runner and explicit scenario bindings that preserve those assertions. A missing browser or service remains a prerequisite to measure later. Do not switch to another product surface merely to make a check pass.
