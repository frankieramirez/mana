# Charting milestones

Use the conversation's destination, milestone outcomes, and order as the starting point. Ask only for missing decisions that materially change the roadmap; group independent questions with a recommended answer when helpful. Do not repeat questions already answered or require a fixed interview sequence.

The destination states what will be true when the roadmap is complete. Milestones are observable outcomes whose order reflects dependencies. Choose their number and size to fit the goal. Put outcomes that remain too uncertain to name under **Not yet planned**, and record explicit exclusions under **Out of scope**.

Load `CONTEXT.md` or a relevant document in `docs/adr/` only when it helps resolve a specific uncertainty. Existing files alone are not a reason to read them all.

`you-pick`, "make the decisions", or "you pick" authorizes recommended choices. Briefly state choices taken so the user can correct them. A request to create a roadmap from supplied outcomes already authorizes creation; do not add a confirmation round. A request for a draft or review ends with the proposed chart until publication is authorized.

Charting is ready when the destination and ordered milestone outcomes are clear enough to write. Continue creation under existing authorization, asking only when a material decision remains unresolved.
